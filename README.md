# JobTrial AI — Practical Work Simulations 

**Try the work, not just the interview.** JobTrial AI turns a job description into a role-aligned, hands-on work trial. Learners edit starter project files, run automated checks, and save evidence-based results. Designed as a student hackathon prototype.

## What it does

- Accepts job descriptions by pasting text or uploading supported documents.
- Suggests practice tracks based on job requirements, with a choice of coding language where supported.
- Offers five challenge levels: **Easy (10–25%)**, **Intermediate (26–45%)**, **Advanced (46–65%)**, **Hard (66–85%)**, and **Expert+ (86–100%)**. The percentages are **challenge-intensity selectors**, not measured difficulty or job-readiness percentages.
- Offers two verified task alternatives per level for the supported project tracks. Changing the percentage by 1 point or using **Switch next task** can switch between those alternatives. This is **not** unlimited AI-generated grading.
- Displays editable solution/helper files plus read-only task instructions and sample data.
- Runs supported Python and JavaScript grading in restricted local Docker containers and compares outputs with trusted tests.
- Displays per-test feedback and records submitted assessment reports in a local SQLite database.
- Optionally uses Hugging Face Inference Providers to tailor fictional team-lead briefs and scenario descriptions to the job advertisement. **The trusted task contracts and reference tests are not generated by the language model.**

## Current coverage and limitations

The verified multi-file project tracks cover **JavaScript frontend**, **JavaScript backend**, and **Python AI/ML**, with 5 levels and 2 task alternatives per level/track (30 alternatives in total, drawn from 15 main contracts and their alternates). Other legacy task paths may offer narrower evaluation or human-reviewed deliverables. A Docker image being installed does not imply a fully supported task track for every programming language.

Tests evaluate specific task behavior; scores are **not** a certification of hiring readiness. The project is not a production-grade public code execution service. **Do not expose its code runner to the public internet.**

## Tech stack

- **Frontend:** React 19, TypeScript, Vite
- **Backend:** Python, FastAPI, Uvicorn
- **Optional AI:** Hugging Face Inference Providers
- **Sandboxed local code checks:** Docker Desktop (Node.js and Python images for verified project packs)
- **Local history:** SQLite (`backend/data/history.sqlite3`, ignored by Git)

## Local setup — Windows / VS Code

Prerequisites: Python 3.10+, Node.js/npm, Docker Desktop for container-based checks, and an existing Python environment (you can reuse it).

1. Open the `JobTrial_AI` folder in VS Code. Use its root for backend commands.
2. Install backend packages **once** in the Python environment of your choice:

   ```powershell
   python -m pip install -r backend\requirements.txt
   ```

3. Build the frontend **once**, or after changing frontend files:

   ```powershell
   cd frontend
   npm install --include=dev
   npm run build
   cd ..
   ```

4. Copy `.env.example` to `.env` in the project root and edit only the local `.env`:

   ```dotenv
   HF_TOKEN=hf_YOUR_OWN_TOKEN
   HF_MODEL=openai/gpt-oss-20b:fastest
   HF_TIMEOUT=50
   JOBTRIAL_ENABLE_DOCKER=true
   APP_ENV=development
   ```

   Obtain a Hugging Face token with Inference Providers permission. The AI option may require an available provider/model and usage credits. Without a token, select **Offline demo only** in the UI to use verified local templates (no AI-authored brief). Never commit `.env`.

5. Start Docker Desktop. For the verified project packs, pull images if needed:

   ```powershell
   docker pull python:3.12-alpine
   docker pull node:24-alpine
   docker version
   ```

6. Start the app in your **existing Python environment** from the repository root:

   ```powershell
   python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
   ```

   Or run `RUN_FAST.bat` from the root. It starts using your current Python setup; it does not create a new virtual environment or reinstall dependencies.

7. Open **http://127.0.0.1:8000**. API health: **http://127.0.0.1:8000/api/health** (`version` should report `6.0.0`). API docs: **http://127.0.0.1:8000/docs**.

## Walkthrough

1. Paste a job ad, e.g. `AI Engineer Internship — Python, machine learning, precision, recall, classification, evaluation, RAG`.
2. Choose **Easy** or **Expert+** and generate a trial; compare the assignment requirements.
3. Open `src/solution.py` or `src/solution.js`. Read the task brief and sample data; edit the solution and optionally helpers.
4. Click **Run checks**. Observe the pass/fail results from the local grader.
5. Click **Submit work** and review **My reports**. The report stays on your device unless you deliberately move the local database.

For JavaScript, try `Junior JavaScript Developer — Node.js, REST APIs, dependencies, deployment, testing`. To validate grading, submit both an intentionally incorrect solution and a correct one and compare reports.

## Development checks

From the root (install `pytest` in your environment if needed):

```powershell
python -m pytest -q
```

The v6 development run reported 83 passing backend tests. Docker, AI-provider calls and frontend behavior should still be checked on the target machine.

## Troubleshooting

- **`'tsc' is not recognized`:** Run `npm install --include=dev` inside `frontend`, then `npm run build`.
- **`404` at `/`:** Build the frontend (`cd frontend; npm run build`) and restart the backend.
- **Docker tests unavailable:** Check Docker Desktop, `docker version`, required images, `JOBTRIAL_ENABLE_DOCKER=true`, and restart FastAPI.
- **AI returns malformed JSON / 503:** Check model availability, HF token and provider credits; retry or explicitly select offline demo mode.
- **Still showing an old task:** Check `/api/health` for v6 and ensure you rebuilt the frontend after updating UI code.

## Security and privacy

- `.env`, local databases, virtual environments, `node_modules`, compiled frontend files and Python cache folders are ignored by Git.
- AI-generated text and uploaded job descriptions may be sent to the chosen Hugging Face provider when AI mode is enabled. Avoid pasting confidential personal information.
- Docker restrictions help with local experimentation, but do **not** make arbitrary untrusted code execution safe for an internet-facing multi-user deployment. Additional isolation, resource limits, authentication, abuse controls and security review are required.
